# Pokémon 专用问答模型

本项目计划构建一个“本地知识库 + 通用大模型 API”的宝可梦问答服务。核心目标不是重新训练一个记住全部事实的模型，而是让模型在回答前查询可追溯、区分游戏版本的本地数据，并在回答中给出来源与适用范围。

项目采用同一代码库发布两个版本：

- **官方版（原作全世代）**：内部标识 `mainline`，以主系列游戏的版本化图鉴和机制资料为基础，优先开发。
- **PokeMMO 特别版**：内部标识 `pokemmo`，在 `mainline` 基础上应用经过核验的 PokeMMO 差异覆盖层。

“官方版”是产品版本名，不代表全部数据由 Pokémon 官方提供；每条回答仍需如实标注官方资料、社区整理或推导。

当前状态：官方版已导入全国图鉴 1,025 个物种的结构化详情、全部 1,351 个宝可梦形态记录、完整招式/特性/道具目录及按版本学习面。已具备精确筛选、多对象比较、进化链、实体关系、章节 RAG 和组合标签检索；2,223 个标签形成 46,662 条实体关联并覆盖全部 4,559 个实体。另已从固定提交的 Pokémon Showdown 规则数据核验 901 个招式，导入 37 类、3,171 条当前主系列招式机制分类关系。PokeMMO 覆盖层尚未导入真实差异数据。

## 已确定的技术方向

- MVP 聚焦宝可梦主系列游戏：宝可梦、形态、属性、种族值、特性、招式、进化、学习面与版本差异。
- 结构化事实走 SQL/规则工具；图鉴描述、官方公告等文本再走检索增强生成（RAG）。
- 事实不依赖模型参数记忆；微调只用于表达风格、意图识别或工具调用，不用于灌注经常变化的知识。
- 每条事实保存来源、上游提交、抓取时间、语言、世代/版本与置信等级。
- PokéAPI 的 CSV/静态 JSON 作为第一阶段主数据，官方网页只做人工核验和链接引用，不批量抓取。
- 招式、特性和道具说明优先使用 PokéAPI 中按版本保存的游戏内简体中文文本；缺失时使用带明确署名和非商业限制的百科补缺层，不使用机器翻译冒充官方文本。
- 未指定版本的道具和特性问题默认追加第九世代 `scarlet-violet` 规则下的精确倍率、概率或公式；结构化机制与中文展示文本分开保存。
- 章节 RAG 使用 SQLite FTS5 `trigram` 中文全文索引，并结合实体关联召回和本地重排；每段保存章节路径、版本范围、来源、许可、核验日期与内容哈希。
- 宝可梦、招式、特性和道具使用统一多对多标签体系；标签由结构化事实确定性生成并附带证据 JSON，可用于组合查找和未来大模型工具调用。

## 试点运行

Windows 用户可直接双击项目根目录中的 [启动项目.cmd](启动项目.cmd)，程序会自动进入正确目录、检查数据库并打开连续中文问答界面。无需选择菜单，直接输入“皮卡丘的种族值是多少？”或“十万伏特是什么招式？”即可；`/audit`、`/eval` 和 `/exit` 分别用于审计、测试和退出。

需要测试大模型理解能力时，先双击 [配置大模型.cmd](配置大模型.cmd) 填写接口地址、协议、模型和密钥，再照常运行 `启动项目.cmd`。未启用或未填写配置时仍保持完全本地模式。

需要让QQ机器人或其他本机程序调用时，可双击 `启动知识服务.cmd`。服务仅监听 `127.0.0.1:8766`，提供 `GET /health` 和 `POST /v1/answer`；它读取本项目自己的 `config/llm.env`，不会向调用方暴露API密钥。每个HTTP问题使用独立对话上下文，避免不同群成员之间串话；大模型失败时自动回退本地规则引擎。模型默认单轮最多15秒、至多3轮工具调用、整题最多35秒；本地规则也无法回答时会返回明确的终止信息。当前 `edition=mainline`，PokeMMO覆盖层完成前，调用方必须明确标注资料范围。

命令行方式：

```powershell
.\tools\sync_pokeapi.ps1
.\tools\sync_chinese_texts.ps1
.\tools\sync_pokemon_showdown.ps1
python .\tools\build_pilot.py
python .\tools\run_pilot_evaluation.py
python -m unittest discover -s tests -v
```

无需安装第三方 Python 包即可完成当前数据构建和离线测试；付费大模型默认关闭。

## Git 仓库与本地数据

仓库只保存源代码、配置模板、数据源清单、同步脚本、Schema、测试和文档。以下内容不会提交：

- `config/llm.env` 中的真实模型地址与 API 密钥；
- `logs/` 中的模型工具轨迹；
- `data/raw/` 中可以由固定提交重新下载的上游快照；
- `data/curated/*.db` 中可以重新生成的 SQLite 数据库。

首次克隆后依次运行上面的三个同步脚本和数据库构建命令，即可恢复完整本地知识库。`config/llm.env.example` 可复制为私有的 `config/llm.env`，但后者始终由 `.gitignore` 排除。
