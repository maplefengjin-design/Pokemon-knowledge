# 查询工具与实用标签

## 精确查询工具

`KnowledgeService` 当前提供以下组合能力：

- `filter_species`：按基础形态种族值、世代、属性、特性、标签和传说分类执行 SQL 筛选；
- `compare_species`：比较多个宝可梦的六项种族值、总种族值、身高、体重、捕获率和基础亲密度；
- `get_evolution_chain`：取得完整进化分支、触发方式、版本组和原始条件字段；
- `get_species_relations`：聚合形态、属性、特性、蛋组、地区图鉴、进化、标签，以及可选版本的学习面和携带物；
- `get_species_learnset`：查询宝可梦学习面；未指定版本时自动采用该宝可梦最新有记录的版本；
- `can_species_learn_move`：判断宝可梦能否学习某招式，并区分“不能学习”和“指定版本没有其学习面”；
- `move_learners`：从招式反查指定版本组中的学习者；
- `get_entity_tags`、`search_by_tags`、`match_tags_in_text`：列出、组合搜索和从自然语言提取标签；
- `search_passages`：检索复杂机制章节。

`src/pokemon_knowledge/tool_api.py` 为这些能力提供与模型厂商无关的 JSON Schema 和白名单调度器。未来接入任意支持工具调用的大模型时，只需转换外层消息格式，不需要改数据库查询逻辑。

学习面结果包含 `version_selection`、`latest_available_version_group`、`available_version_groups`、`status` 和 `status_zh`。`status=unavailable_in_version` 表示指定版本没有该宝可梦的学习面，不能解释为数据库全局缺失，也不能直接解释为不能学习。

## 标签模型

`tags` 保存规范标签，`entity_tags` 保存实体与标签的多对多关系、生成方式、置信度、证据 JSON 和来源，`tags_fts` 提供中文全文候选索引。当前共有 2,223 个标签、46,662 条关联，覆盖全部 4,559 个物种、招式、特性和道具实体。

宝可梦标签包括分类、世代、属性、特性、地区图鉴、颜色、外形、栖息地、成长速率、性别、传说分类、蛋组、形态、进化阶段、六项精确种族值、总种族值、高种族值和基础点数产出。招式标签除世代、属性、物理/特殊/变化分类、精确威力、威力区间、优先度和概率效果外，还包含 37 类当前主系列机制分类，例如接触、切割、风、球和弹、啃咬、拳、波动、声音、粉末、舞蹈及各类招式选择/复制限制。特性标签记录世代与主系列范围；道具标签记录类别和口袋。

机制分类另以 `move_mechanic_categories`、`move_mechanic_memberships` 和 `move_mechanic_coverage` 保存，而不是只保存成展示标签。这样工具可以精确判断“精神利刃是切割类但不是接触类”，同时区分“已核验但没有正向分类”和“来源未覆盖”，也可以按多个机制分类组合检索。当前核验 901 个招式，其中 846 个至少有一个正向分类，共导入 37 类、3,171 条关系；来源是固定到提交的 Pokémon Showdown `data/moves.ts`，规则范围标记为 `current-mainline`。`allyanim` 只影响动画展示，已明确排除。

地区图鉴标签来自 `pokemon_dex_numbers.csv` 的实际成员关系，不用初登场世代推断。诸如“关都地区图鉴宝可梦”和“卡洛斯地区图鉴宝可梦”可以同时关联到同一物种。

## 当前语义约定

- `filter_species` 当前固定比较基础形态；形态级筛选以后单独扩展；
- “普通宝可梦”暂定义为 `is_legendary = 0 AND is_mythical = 0`，因此究极异兽等是否应排除需要用户或上层模型进一步说明；
- 宝可梦的特性标签按全部已导入形态生成，而属性和种族值标签默认使用基础形态；
- 自动标签只表达数据库已有事实，不根据模型常识猜测战术定位。

```text
基础形态速度超过150的普通宝可梦有哪些？

土居忍士的进化型是什么？
超梦有哪些标签？
紫色且超能力属性的宝可梦有哪些？
高威力电属性招式有哪些？
```
