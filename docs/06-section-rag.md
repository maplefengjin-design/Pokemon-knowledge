# 章节 RAG 设计与试点

## 当前实现

章节 RAG 与实体主表分开保存。`knowledge_documents` 记录页面级来源与许可，`knowledge_passages` 记录可独立检索的小节、适用世代和版本，`passage_entities` 建立章节与宝可梦、招式、特性或道具的多对多关系，`knowledge_passages_fts` 使用 SQLite FTS5 `trigram` 索引中文标题、路径与正文。

检索分三步：先用中文全文索引取得候选，再通过已识别实体补充召回，最后用字符 n-gram、问题意图和实体关系在本地重排。该方案无需第三方包，也不会调用付费模型。未来接入大模型时，模型只负责理解问题和整理证据，事实仍来自返回的章节与结构化查询。

## 试点范围

首批有 2 篇文档、6 个章节片段：

- 挥指：第九世代随机选择流程、不会使出的招式、特殊互动；
- 再来一次：第九世代效果、使用失败条件、第二至第七世代历史变化。

内容是项目根据标注来源重新整理的机制摘要，不是整页复制。每个文档保存来源 URL、来源类型、许可、核验日期和修订标记；每个片段保存 SHA-256 内容哈希。

## 查询接口

`KnowledgeService.search_passages()` 接受自然语言问题、可选实体列表、世代、版本组、版本域和返回数量。默认按第九世代 `scarlet-violet` 检索；指定旧版本时，会自动使用该版本组所属世代并排除不适用的第九世代片段。

自由问答层会把“不会使出哪些招式”“使用失败条件”“为什么”“互动”“历史变化”等深度问题路由到章节 RAG；普通的威力、命中、PP 等查询仍走结构化字段。

## 验证

执行：

```powershell
python tools/build_pilot.py
python -m unittest discover -s tests -v
python tools/run_pilot_evaluation.py
```

测试覆盖中文无实体名全文召回、实体关联改写召回、失败条件问答、旧世代范围过滤、FTS 与章节行数一致性、来源元数据和既有结构化回归测试。

## 后续扩展准则

新增章节优先覆盖高频且结构化短描述无法表达的规则：随机调用、失败条件、排除集合、招式复制、状态持续、跨招式/特性/道具互动和世代差异。高风险的完整名单与倍率仍应晋升为规则表，章节负责解释与提供上下文；向量检索只有在专业改写问题集上显著优于当前 FTS 基线后再引入。
